- (decision) Stakes: personal project, treated seriously (proper FRs/NFRs, not throwaway). Mode: Coaching path, journey-led entry point (consumer map-browsing app + admin as second protagonist).
- (decision) Reviewed wander-eire-map-mockup.jsx: confirms filter chips, tap-pin bottom sheet with tick/save, category icons (Mountain/Landmark/Eye/Waves/Tent). New details not in brief: search bar ('Where to next?'), profile icon top-right, dashed route lines connecting pins on map (unclear if decorative or a real route-planning feature - to clarify with user).
- (decision) Competitor research (Roady, NZ): validates map->pin->tick-off->save/plan as proven loop. Roady has leaderboards/badges/photo-verified visits + drive-time trip planning + commerce (campervan/tour booking commissions) + freemium subscription. Key lessons for Wander Eire: (1) went free->paid mid-flight, badly damaged trust - stay genuinely free per brief; (2) users complained of incomplete/missing coverage despite editorial curation - thoroughness matters more than breadth; (3) UGC location submissions were slow/inconsistently moderated - tight curation loop is a differentiator; (4) gamification/leaderboard is optional, not required for the core loop to work, consistent with brief's decision to defer social layer.
- (decision) Dashed lines between pins on mockup are decorative only, not a route-planning/itinerary feature - out of scope for v1.
- (decision) UJ-1 confirmed: Mary opens app -> overview map of Ireland with her location shown -> zooms to nearby pins -> taps pins for details/photos -> gets directions -> leaves app to drive -> returns to tick off or browse next. Search is secondary (top toolbar), map exploration is primary/encouraged path. Directions v1 = display address + Eircode for manual copy-paste into Google/Apple Maps (no deep-link in v1, that's a later enhancement). No separate 'plan ahead the night before' journey - saves happen opportunistically within a browsing session, not as a dedicated pre-trip planning flow.
- (decision) UJ-2 (Admin add location) confirmed: Admin dashboard form with fixed preset fields (matches locations schema in brief). Publish is immediate on submit, no draft/review gate needed - 'next cycle' language was just describing non-instant expectations, not a deliberate staging workflow. Pin placement supports BOTH: click-to-drop on a map AND type address/Eircode with auto-geocode - admin can use whichever is convenient per entry.
- (decision) Anonymous browsing gate: map browsing is open to all, but viewing full pin details is capped at 3 pins total (lifetime, unauthenticated) before prompting free account signup. Offline/poor-signal handling for in-app photo/comment uploads at rural spots is explicitly OUT of scope for v1 - upload fails/retries manually, revisit at PWA/Capacitor polish phase. Signed-in upload flow (UJ-3) happens in-app, at the spot, in real time.
- (decision) UGC moderation: admin reviews photos/comments before they go live (pending approval queue), not live-then-remove. GDPR: baseline compliance treated as real v1 NFRs - privacy policy, account deletion removes personal data, clear consent for photo uploads.
- (decision) Audience/goal: starts as personal/close-circle use (builder's own trips + friends/family), but built with intent to become a real small public launch to strangers eventually - not designed as throwaway. Launch content bar: minimum 1 activity/location per county (~32 total across all 32 counties) before v1 counts as launched/usable.
