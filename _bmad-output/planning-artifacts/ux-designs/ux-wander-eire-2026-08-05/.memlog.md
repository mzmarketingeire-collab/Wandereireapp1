- (decision) Design system is locked from PROJECT-BRIEF.md: palette (Cream/Ink + 5 category hues), type (Space Grotesk/Inter/IBM Plex Mono), and circular 'tack' pin concept (not teardrop). Not open for redesign in this UX pass.
- (event) Sources confirmed: PROJECT-BRIEF.md, PRD (prd-wander-eire-2026-08-05/prd.md), reference mockup wander-eire-map-mockup.jsx — all already read and applicable.
- (assumption) Form factor: mobile-first PWA per PRD §13/§6.1 phase 3; React+Vite+MapLibre GL JS web app, installable. No native app in v1.
- (decision) Map/list toggle (FR-4): List is a drawer/sheet that slides up over the map (map stays mounted as the base layer underneath), not a tab switch.
- (decision) Detail Sheet (FR-6): always opens full-screen (dedicated view) on pin/list-item tap — no half-sheet peek intermediate state.
- (decision) Search (FR-5): live as-you-type results list replaces/overlays the map; tapping a result jumps map + opens detail sheet.
- (decision) Pin clustering: none in v1 — pins render individually and may overlap at low zoom; user zooms in to separate. Revisit if/when location count grows much past initial county coverage.
- (decision) Anonymous Gate (FR-8): on the 4th distinct location tap, a blocking modal appears offering sign-up/sign-in — the Detail Sheet does not open at all until the account is created (no teaser/blurred content).
- (decision) Auth (FR-9): sign-up/sign-in renders as a modal/sheet overlay on top of the triggering context (gate or profile icon tap), not a dedicated route — closes back to where the user was, including reopening the location that triggered the gate.
- (decision) Profile (FR-13): Ticked and Saved shown as two switchable tabs, each a list/grid using the map's category-colour + tack pin visual language.
- (decision) Profile shows a lightweight progress stat (e.g. counties/locations ticked) — reinforces the 'personal record of the country over time' vision from PRD §1, explicitly not framed as a leaderboard/comparison.
- (decision) Contribution flow (FR-14/15): 'Photos & Comments' is a dedicated section scrolled into the full-screen Detail Sheet — shows approved content as a feed, user's own pending submissions marked 'pending review', inline add button (not a separate FAB flow).
- (decision) Admin route (FR-18-23): reuses the same bright/bold consumer visual language (palette/type/pin styling) rather than a utilitarian admin-panel look.
- (decision) Admin route form factor: responsive, works on mobile as well as desktop — desktop is the primary bulk-entry case but mobile quick-edits from the field are supported, not a dead end.
- (decision) Moderation queue (FR-23): list view of pending items (thumbnail, submitter, location, text) with inline Approve/Reject buttons per row — not a one-at-a-time review screen.
- (decision) Category icons locked from mockup: Mountain=Trail, Landmark=Historic, Eye=Viewpoint, Waves=Beach/Coast, Tent=Camping (lucide-react icon set). New categories get new icons following the same logic.
- (decision) Empty/error state copy: warm, in-voice tone consistent with 'Where to next?' — not neutral/functional boilerplate.
- (decision) Loading states: simple centered spinners for in-flight content (map/pins, detail sheet, uploads) — no skeleton/shimmer placeholders in v1.
- (decision) EXPERIENCE.md depth: lean — key decisions and named flows captured clearly, component/state tables kept to essentials rather than exhaustive enumeration. Reflects solo-build usage of this doc.
- (event) Imported wander-eire-map-mockup.jsx into imports/ as the visual reference for map screen, filter chips, pin interaction, and bottom sheet.
- (decision) GDPR UI touchpoints: privacy policy linked from the auth modal footer and profile menu; upload consent is a one-time acknowledgment (at signup or first upload), not shown per-submission; account deletion is a confirm-twice action inside profile settings, clearly separated from other actions.
- (decision) Admin Add/Edit Location form (FR-19): single page grouped into labeled collapsible sections (Basics, Location & Access, Cost & Distance, Photos) rather than a flat long form or multi-step wizard — one submit, less overwhelming than a flat list of ~10 fields.
